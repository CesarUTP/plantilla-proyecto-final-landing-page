# Guía del informe en Word (Parte 6)

El informe es un documento de Word (.docx) **grupal** que cuenta cómo trabajó el equipo en GitHub y qué aprendió. Se entrega junto con los enlaces al repositorio y a la página publicada.

**Reglas generales:**
- Máximo **8 páginas**, sin contar la portada.
- Archivo nombrado **Proyecto_Final_Grupo_N** (con el número de tu grupo), en formato `.docx`.
- Redacción formal y clara. Las figuras y tablas se numeran, llevan título y fuente.
- Lo envía un solo integrante en nombre del grupo.
- Se redacta entre todos, por ejemplo en un documento compartido de Word en línea o de Google Docs, y al final se exporta a `.docx`.

## Sección 4: GitHub como herramienta colaborativa

Usa lo aprendido en los Módulos I a IV. Completa esta tabla con **ejemplos que ocurrieron en tu repositorio** (no ejemplos generales):

| Concepto | Clasificación o ejemplo en el repositorio del grupo |
|---|---|
| Tiempo y espacio | ¿Se trabaja al mismo tiempo o en tiempos distintos (sincrónico o asincrónico)? ¿En el mismo lugar o a distancia (colocado o distribuido)? |
| Función | ¿Es de comunicación, de coordinación o de colaboración en contenido? Explica con un ejemplo. |
| Nivel de estructura | ¿Es una herramienta muy estructurada o poco estructurada? ¿Por qué? |
| Awareness social | Ejemplo: cómo se ve quién es cada colaborador (foto, usuario, perfil). |
| Awareness de la información | Ejemplo: cómo se sabe el estado de un pull request o de un issue. |
| Awareness del espacio de trabajo | Ejemplo: cómo se ve quién está cambiando qué (historial, ramas, actividad). |

## Sección 5: las cinco capturas de pantalla (T6.2)

Cada captura va **numerada, con título y fuente** (por ejemplo: "Figura 1. Gráfica de Contributors del repositorio. Fuente: GitHub, captura del grupo").

1. **Contributors:** Insights, Contributors, donde se ven los cuatro integrantes.
2. **Historial de commits:** la lista de commits de `main`, con el usuario de cada autor.
3. **Un pull request con revisión:** con comentarios y aprobación de un compañero.
4. **Issues:** la lista de issues, con responsables y estados.
5. **La página publicada:** vista en el navegador con su enlace.

Recorta cada captura para que se lea bien.

## Sección 7: desafíos y aprendizajes

Tres desafíos o más. Algunos ejemplos (no son obligatorios): un conflicto de fusión, un error de Git, un integrante que no podía subir cambios, una imagen que no cargaba en la página publicada o desacuerdos sobre el diseño. Para cada uno: **qué pasó, cómo se resolvió y qué aprendió el grupo**. Termina con dos o tres líneas sobre qué cambiaría el grupo en un próximo proyecto en equipo.
