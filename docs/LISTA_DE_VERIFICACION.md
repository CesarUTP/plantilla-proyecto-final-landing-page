## Verificación del grupo

- [ ] Cada tarea (T1.1, T2.1, etc.) tiene su entregable en el repositorio o en el README.
- [ ] El repositorio es **público** y se abre en una ventana privada del navegador.
- [ ] Los cuatro integrantes son colaboradores (Settings, Collaborators).
- [ ] La rama `main` está protegida: exige pull request y una aprobación.
- [ ] Hay al menos **8 issues**, todos con responsable, y cada integrante tiene issues asignados.
- [ ] Los cuatro integrantes aparecen en **Insights, Contributors**, con commits en al menos tres días distintos.
- [ ] Los pull requests fueron revisados por un compañero distinto del autor.
- [ ] La página tiene todas las secciones: encabezado con llamado a la acción, propuesta de valor, tres o más características, equipo y pie.
- [ ] La página se ve bien en celular y en computador, las imágenes tienen texto alternativo y los enlaces funcionan.
- [ ] La página está **publicada con GitHub Pages** y el enlace abre sin errores.
- [ ] El README está completo, sin el bloque "LEER PRIMERO" y sin textos que digan COMPLETAR.
- [ ] **El uso de IA se nombra siempre, con el lugar donde se usó:** en la casilla de cada pull request, en la tabla del README y en el informe (o se declara que no se usó).
- [ ] El README acredita los recursos de terceros.
- [ ] El **informe en Word** está completo: máximo 8 páginas sin portada, nueve secciones, cinco capturas numeradas, tabla de aportes que coincide con GitHub, tabla de IA y referencias en APA 7.
- [ ] El archivo del informe se llama `Proyecto_Final_Grupo_N.docx`.
- [ ] Ningún archivo contiene contraseñas, claves, tokens ni datos personales reales.
